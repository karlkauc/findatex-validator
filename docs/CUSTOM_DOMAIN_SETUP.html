Eigene Domain für die Web-App: findatex-validator.eu

Anleitung, um die in Cloud Run laufende Web-App (Region europe-west4) unter findatex-validator.eu und www.findatex-validator.eu erreichbar zu machen. DNS-Verwaltung erfolgt bei domaintechnik.at.

1Domain-Eigentum bei Google nachweisen einmalig

  1. Google Search Console öffnen.
  2. „Property hinzufügen" → Typ „Domain" → findatex-validator.eu eingeben.
  3. Google zeigt einen TXT-Record an, z. B.: 
    google-site-verification=abcdef12345...
  4. Bei domaintechnik im DNS-Editor:
    • Typ TXT, Host/Name @ (oder leer = Apex), Wert exakt wie angezeigt.
  5. Zurück in Search Console → „Bestätigen". DNS-Propagation 1–10 Minuten.

Erst wenn das Häkchen grün ist, geht es mit Schritt 2 weiter.

2Custom Domain in der Google Cloud Console anlegen

  1. Cloud Console → Cloud Run → Region europe-west4 → Service findatex-validator-web.
  2. Tab „Custom Domains" (oder oben „Manage Custom Domains" → „Add Mapping").
  3. Service auswählen: findatex-validator-web.
  4. Zwei Mappings nacheinander anlegen:
    • erst www.findatex-validator.eu
    • dann findatex-validator.eu (Apex)
  5. Google zeigt pro Mapping eine Liste von DNS-Records, die du eintragen sollst — genau diese Werte verwenden, nicht die unten als Beispiel.

Für die Subdomain bekommst du typischerweise einen CNAME, für den Apex 4× A + 4× AAAA.

3DNS-Records bei domaintechnik.at eintragen

Im DNS-Editor der Domain findatex-validator.eu:

Typ Host/Name Wert (Beispiel — übernimm den aus GCP-Console) TTL
TXT @ google-site-verification=… (aus Schritt 1) 3600
CNAME www ghs.googlehosted.com. (Punkt am Ende!) 3600
A@216.239.32.213600
A@216.239.34.213600
A@216.239.36.213600
A@216.239.38.213600
AAAA@2001:4860:4802:32::153600
AAAA@2001:4860:4802:34::153600
AAAA@2001:4860:4802:36::153600
AAAA@2001:4860:4802:38::153600

Wichtig:

  • Bei CNAME www: Wert mit Punkt am Ende — sonst hängt domaintechnik die eigene Domain nochmal dran (ghs.googlehosted.com.findatex-validator.eu = kaputt).
  • Falls domaintechnik bereits A-Records für @ mit einer Parking-Page hat — diese löschen. Sonst zeigt der Apex auf zwei Ziele und es ist Zufall, was kommt.
  • Falls du E-Mail-Aliase nutzt (z. B. office@findatex-validator.eu): die existierenden MX-Records von domaintechnik nicht anfassen.
  • TTL niedrig lassen (300–3600), bis alles steht — danach hochsetzen.

4Auf Cloud Run zurückgehen & Cert abwarten

  1. Cloud Run → Custom Domains: Status startet bei „Pending" → „Certificate provisioning" → „Active".
  2. Dauer: meist ~15 Minuten, in Ausnahmefällen bis zu 24 Stunden.
  3. Google stellt das TLS-Zertifikat automatisch aus (Google-Trust-Services / Let's Encrypt), kostet nichts.
  4. Sobald grün: https://www.findatex-validator.eu und https://findatex-validator.eu liefern beide die App, beide mit HTTPS.

5Validierung

# DNS-Propagation prüfen
dig +short www.findatex-validator.eu CNAME
dig +short findatex-validator.eu A
dig +short findatex-validator.eu AAAA

# App-Zugriff
curl -I https://www.findatex-validator.eu
curl -I https://findatex-validator.eu

Beide curl-Aufrufe sollten HTTP/2 200 liefern und ein gültiges Google-Trust-Services-Zertifikat vorzeigen.

Was du in der App selbst nicht ändern musst

  • Quarkus-Konfiguration, CORS, docker-compose.yml — alles unverändert. Cloud Run terminiert TLS und proxied weiter an den Container auf Port 8080.
  • application.properties-quarkus.http.host/Port bleibt wie er ist.
  • Usage-Stats-Endpoint, Ingest-Token, Neon-Anbindung — alles unverändert.

Offene Punkte & Hinweise

  • Cloud-Run-Service-URL bleibt parallel erreichbar (*.run.app). Optional in Cloud Run → „Networking" den direkten URL-Zugriff deaktivieren — aber dann muss das Custom-Domain-Mapping zwingend funktionieren.
  • HTTP→HTTPS-Redirect: Cloud Run macht das automatisch.
  • Apex-Mapping dauert oft länger als die Subdomain — wenn www schon grün ist und Apex noch nicht, Geduld bis 24 h, nicht neu anlegen.
  • GitHub-Feedback-URL (FINDATEX_WEB_FEEDBACK_GITHUB_REPO) und Desktop-endpointUrl ggf. auf die neue Domain aktualisieren.
  • MX-Records für office@findatex-validator.eu sind unabhängig vom Cloud-Run-Mapping — beim DNS-Bearbeiten nicht versehentlich löschen.
